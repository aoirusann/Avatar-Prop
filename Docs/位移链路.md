# 位移链路（PhysBone → 道具）

## 手柄：Bone 上的 VRCPhysBone

`Bone base/Bone` 上有一个 `VRCPhysBone`：

| 设置 | 值 | 含义 |
|---|---|---|
| `Parameter` | `AvatarProp/Grabbing` | 抓取时 VRChat 会把 `Grabbing_IsGrabbed` 置 true |
| `Allow Grabbing` | true（Self + Others） | 谁都能抓 |
| `Radius` | 0.1 | 握手柄的判定半径 |
| `Immobile` | 1 | 松手后不随 avatar 走动而移动、也不回弹 |
| `Gravity` | 0 / `Pull` 0 / `Spring` 0 / `Stiffness` 1 | 抓到手就"硬跟"，松手就停在原地 |

`Bone` 的子物体 `Resyncy boi` 就是**抓取参考点**（同时也是 `AvatarProp.Distance` 的发送体）。

> 注意：PhysBone 的属性（含 `Immobile`）**不能靠动画曲线驱动**。不要给状态 clip 添加 `immobile` 曲线——Unity 在 play 时仍会按曲线把它写成 0，从而破坏"世界锚定"（表现为移动角色时手柄被拖着绕圈）。

## 道具位置不是父子跟随，而是约束

道具网格在 `Position/Rotation/Object container` 下，而 `Position` 上是一个 `VRCPositionConstraint`，它的来源按权重混合：

```
Position (VRCPositionConstraint) 源:
  source0 = Resyncy boi     （实时手柄位置）
  source1 = Reset transform  （复位锚点；本 fork 挂到头部）
  source2 = Save position   （锁存快照）
  source3 = Hand            （Hand tracker）
```

各状态把权重压到不同来源（数据来自动画曲线）：

| 状态 | 主要来源 | 说明 |
|---|---|---|
| Off | source1 = `Reset transform` | 关闭，停在复位点 |
| On / Enabled | source0 = `Resyncy boi` | 手柄静止在复位点，所以看着也在复位点 |
| Grabbed | source0 = `Resyncy boi` | 跟手，见 [大状态-被抓取Grabbed](./大状态-被抓取Grabbed.md) |
| Prop dropped | source2 = `Save position` | 锁存，见 [锁存机制](./锁存机制.md) |

## 为什么"停在世界原地"

根物体 `Avatar Prop` 被约束到 `!Resources/000.prefab`（世界原点的一个空物体），所以整个系统的坐标是**世界固定**的；再加上 `Bone` 的 `Immobile=1`，手柄在被摆到某处后不再移动。两者叠加，道具就能"停在世界上的原地"。更细的锁存过程见 [锁存机制](./锁存机制.md)。

> 本 fork 的不同：`Reset transform`（复位锚点）本身被 ArmatureLink 到了 **Head 骨骼**，所以道具的"家 / 初始位置"（`Position` 的 `source1`）是**跟着头走**的；上面说的"世界固定"针对的是根物体与放下后的锁存快照，两者并不冲突。
