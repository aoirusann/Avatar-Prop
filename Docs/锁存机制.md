# 锁存机制

## 一句话

放下时，系统**把两个"锁定用"的约束关掉（冻结成快照），再把道具的约束来源切换到这两个快照**；由于根物体钉在世界锚点上，快照就是世界坐标，道具因此停在原地。

## 两个"锁定体"

```
Save position (VRCPositionConstraint)
   源 = Delay position w1  +  Hand w0.6

Save rotation (VRCRotationConstraint)
   源 = Rotation (AimIK) w1
```

- 抓取时它们**一直开着**（`m_Enabled = 1`），所以它们**持续跟随**当前的实时姿态：`Save position` 跟 `Delay position`（→ `Resyncy boi`，即手柄），`Save rotation` 跟 AimIK 的 `Rotation`。
- 放下时动画把它们 **`m_Enabled = 0`**。VRChat 约束被禁用后不再驱动物体，于是这两个物体**停在最后一帧的姿态上**（相当于按了暂停）。

## 切换来源

道具的两个约束的来源权重按状态切换（实测）：

| 状态 | `Position` 主来源 | `Rotation` 主来源 | `Save position` / `Save rotation` |
|---|---|---|---|
| Grabbed | source0 `Resyncy boi` = 1 | source0 `Rotation`(AimIK) = 1 | `m_Enabled = 1`（在跟踪） |
| Prop dropped | source2 **`Save position`** = 1 | source1 **`Save rotation`** = 1 | `m_Enabled = 0`（被冻结） |

所以顺序是：**先让锁定体在后台跟踪 → 松手瞬间关闭锁定体（冻结）→ 道具改去跟随这两个冻结体**。

## 为什么能停在世界

- 根物体 `Avatar Prop` 被 `VRCParentConstraint` 绑到世界锚点 `000.prefab`，整个系统的坐标是世界固定的，冻结下来的姿态就是**世界坐标**。
- 另外 `Bone` 的 PhysBone `Immobile=1`，手柄本身松手后也不回弹——这是"双保险"。真正把道具钉住的是上面的"冻结快照"。
- 注意：`Immobile` 是 PhysBone 属性，**不可被动画驱动**；不要给状态 clip 加 `immobile` 曲线，否则 Unity 在 play 时会把它写回 0，破坏"世界锚定"。
